# 引论

## 编译基本概念

### 程序语言的发展

机器语言 → 汇编语言 → 高级语言。

数字代码 → 符号形式 → 类似数学定义或自然语言的简洁形式。

**编写机器语言**费时而且枯燥，效率较低，**汇编语言**提高了编程的速度和准确度，但依赖机器，移植性差。

### 什么叫编译程序

**翻译程序**：把某一种语言程序（<u>源语言程序</u>）**等价**地转换为另外一种语言程序（<u>目标语言程序</u>）的程序。

<img src="../images/compiler-principle/image_20260825_182957.png" style="zoom:67%;" />

**编译程序（Compiler）**：把某一种<u>高级语言程序</u>等价地转换为另一种<u>低级语言程序</u>（如**汇编语言**或**机器语言**程序）的程序。

诊断编译程序、优化编译程序、交叉编译程序、可变目标编译程序。

<img src="../images/compiler-principle/image_20260825_182958.png" style="zoom:50%;" />

**解释程序**：把源语言写的源程序作为输入，但不产生目标程序，而是**边解释边执行**源程序本身。

## 编译工作过程

把英文翻译为中文：Do you like cake?

- 识别出句子中的一个个单词；（**词法扫描**）
- 分析句子的语法结构；（**语法分析**）
- 根据句子的含义进行初步翻译；（**语义分析和中间代码生成**）
- 对译文进行修饰；（**优化**）
- 写出最后的译文。（**目标代码生成**）

<img src="../images/compiler-principle/image_20260826_113721.png" style="zoom:50%;" />

编译过程一般分为以下阶段：

- 词法扫描
- 语法分析
- 语义分析
- 中间代码生成
- 优化
- 目标代码生成

## 编译的各个阶段

### 词法扫描

任务：**输入**源代码，对构成源程序的字符串进行扫描和分解，**识别出**一个个单词记号（*token*）。

依循的原则：**词法规则**。

描述工具：**正则表达式**和**有限自动机**。

```c
int x = y + 1100;
// 关键字 标识符 赋值符 标识符 加号 整常数 分号
```

<img src="../images/compiler-principle/image_20260827_053653.png" style="zoom:50%;" />

### 语法分析

任务：在词法分析的基础上，根据语言的语法规则把**单词符号串**分解为各类**语法单位**（主谓宾）。

依循的原则：**语法规则**。

描述工具：**上下文无关文法**。

通常输出为**语法树**。

<img src="../images/compiler-principle/image_20260827_055926.png" style="zoom:50%;" />

### 语义分析

任务：使用语法树和符号表中的信息来**检查源程序是否和语言定义的语义一致**。同时也收集类型信息等。

**类型检查**是一个重要组成部分。

通常输出为**注释树**。

### 中间代码生成

任务：对各类不同语法范畴按语言的语义进行初步翻译。

**中间代码**：三元式、四元式、树形结构等。

`Z = X + 0.618 * Y` 翻译成四元式为：

|       | 算符 | 左操作数 | 右操作数 | 结果 |
| :---: | :--: | :------: | :------: | :--: |
| （1） | `*`  |  0.618   |   `Y`    | `T1` |
| （2） | `+`  |   `X`    |   `T1`   | `T2` |
| （3） | `=`  |   `T2    |   `--`   | `Z`  |

### 优化

任务：对前阶段产生的中间代码进行加工变换，以期在最后阶段**产生更高效的目标代码**。

主要包括：*公共子表达式的提取*、*循环优化*、*删除无用代码*等。

### 目标代码产生

任务：把中间代码**变换为特定机器上的目标代码**。

**依赖于硬件**系统结构和机器指令的含义。

目标代码的三种形式：

- 绝对指令代码：可直接运行；
- 可重新定位指令代码：需要连接装配；
- 汇编指令代码：需要进行汇编。

## 几个基本概念

### 遍（pass）

所谓“**遍**”，就是对源程序或源程序的中间表示从头到尾扫描一次。

阶段与遍是不同的概念。一遍可以由若干段组成，一个阶段也可以分若干遍来完成。

有单遍编译器，也有多遍编译器。

单遍费内存，多遍耗时间。

**想获取更高的优化效果一般需要多遍来做**。

### 编译前端与后端

<img src="../images/compiler-principle/image_20260827_223331.png" style="zoom:67%;" />

- **编译前端**：与源语言有关，如词法分析、语法分析、语义分析与中间代码生成、与机器无关的优化。
- **编译后端**：与目标机有关，与目标机有关的优化，目标代码产生。
- **提高编译程序的可移植性**。

## 编译程序生成

以汇编语言和机器语言为开发工具。

- **优点**：可以针对具体的机器，充分发挥计算机的系统功能；生成的程序效率高。
- **缺点**：程序难读、难写、易出错、难维护、生成的效率低。

高级语言开发。

- **优点**：程序易读、易理解、容易维护、生产的效率高。
- **缺点**：难以充分发挥计算机的系统功能，生成的程序效率低。
